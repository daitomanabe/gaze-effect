## 方式の比較と採用判断

同じ入力・361フレームを毎回新しい追跡状態から処理した。比較結果: `build/accuracy-v2/backend-comparison.json` / 同時刻の目元: `build/accuracy-v2/backend-comparison.jpg`。速度は解析・合成のみ。

| 方式 | 補正フレーム | 学習済み方式の採用眼数 / 722 | 中央値 / 95%点 |
| --- | ---: | ---: | ---: |
| 局所補正 + VIDEO | 361 | 0 | 9.23 / 9.95 ms |
| Automatic + VIDEO | 361 | 124 | 10.80 / 32.46 ms |
| Neural trial + VIDEO | 361 | 132 | 31.46 / 32.75 ms |
| Automatic + IMAGE | 356 | 111 | 10.64 / 32.96 ms |

Neural trialにも出力の形状・移動量を確認する条件を残しているため、不採用分は局所補正になる。大きな視線移動では学習済みモデルの結果をそのまま使うと形状が崩れたため、Automaticは小〜中程度の移動で候補を評価する。直接目標を推定する別モデルとの比較ではない。今回の結果だけでVIDEO解析の位置精度や応答遅れが優れているとは断定できない。

Core ML実行プロバイダーも12フレームで実行したが、モデル内120ノード中87ノードが対応し、複数の実行区画に分かれた。全面的なGPU化・高速化を確認したという意味ではない。最終動画のONNX処理はCPU実行を使用した。

## 見た目の確認と未達部分

旧方式で目立っていた二重像・まぶたへのはみ出しは、代表7時点の拡大比較で抑制を確認した。ただし、大きく左右を見る場面では白目が均質・青白く見えることや、虹彩境界が人工的に見えることが残る。高度な目元生成が完成したとは扱わない。

複数の暗い連結領域を検出する補助指標は、旧方式100眼フレーム、最終版57眼フレームだった。これはまつ毛や反射を含む候補数で、二重瞳孔の確定件数ではない。

位置合わせ後の安定区間の平均残差変化は旧方式4.93、最終版8.34（8-bit画素値）で、この指標は改善していない。動かした量・生成領域・圧縮が異なるため、これだけをちらつきの良否とは解釈しない。汎用動画QAのPASSも、目元の自然さ・カメラ目線の正確さの保証ではない。

残る作業:

1. 入力のみからカメラ目線を直接予測するモデルの導入・学習と、現在の方式との比較。戦略で参照した[ECC-Net論文](https://arxiv.org/abs/1906.05378)と、今回導入した[Hsu et al.の公開モデル](https://github.com/chihfanhsu/gaze_correction)は異なる方式。
2. 大角度で隠れていた虹彩・白目を自然に補う、目元に限定した学習済み生成器。現在の局所補完の質感を採用条件に達したとは認めていない。
3. 正解の視線方向・虹彩・まぶたのラベルを持つ評価、異なる人物・眼鏡・暗所・まばたき・出入りの録画による検証。今回の主素材では、強い閉眼を含む実録画の確認はできていない。
4. 本人による簡易キャリブレーションと、その取得に使わなかった映像での評価。画面上の既知点に任意の視線を向ける用途の詳細校正は未実装。
5. 物理カメラを用いた実際の撮影から表示までの計測、必要に応じたネイティブ化。
